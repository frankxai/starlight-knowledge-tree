# First public Atlas slice: product decision

Ship the smallest inspectable public knowledge object. A useful seed earns expansion;
an attractive shell does not earn an automated content factory.

| Dimension | Acceptance |
|---|---|
| Reader job | A reader can find one scoped question, understand the recorded claim, reach its exact evidence locator, state a limitation and export a record with provenance intact. Reader acceptance remains unknown until observed. |
| Agent usefulness | Read-only responses retain stable IDs, source SHA, claim revision, draft/review state, inspection scope and coverage limits. Invalid query or article requests fail explicitly; an agent cannot promote draft evidence by omitting its qualifications. |
| Community value | Corrections and reuse are possible through the existing public repository and portable records. Count an accepted correction or attributable downstream reuse as contribution evidence; page views and agent requests measure reach only. |
| Honest coverage | Show actual populated entries separately from the domain map. Empty disciplines are unreviewed. A dated source inspection is not a live discovery service, systematic search, independent replication or consensus. |
| Rights | Source metadata and original paraphrase carry source-specific rights limits. Preserve the repository's existing MIT code license without inventing rights to third-party full texts or media. |
| Cost discipline | The release requires no request-time model generation, paid retrieval or new backend. Existing hosting/build costs and review time remain measurable costs; actual incremental cost is unknown until recorded. |
| Maintenance | Maintain the released seed before expanding coverage. Reassess affected claims on correction/retraction; repair broken locators without silently changing their scientific standing. Assign one accountable maintainer and retain the source revision of every correction. |

Public release acceptance is a technically inspected reader/evidence/export journey,
independent exact-revision review and verified production binding. Scientific standing
retains its own review receipts. Product usefulness and community adoption retain
their own observed outcomes. None of these receipts substitutes for the others.

The credible baseline is a short manually curated annotated bibliography. Atlas must
earn its added machinery through easier claim inspection, preserved disagreement,
reliable exports and useful corrections. Keep the current source/projection seam;
defer any maintained ingestion promise until correction quality and maintainer
capacity are demonstrated.

Compute cost per accepted contribution from all retrieval/model/build expenditure,
failed attempts and human review time divided by independently accepted reusable
results. With no measured accepted results, unit economics remain unknown. Prioritize
corrections that repair consequential misunderstandings over adding many low-value
entries. Record actual accepted corrections/reuse and reviewer time through existing
GitHub receipts; this slice introduces no new tracking system.
