### 3. At the claimed commit, the gate's own install step cannot succeed
The gate workflow at `cf01893` installs with `npm ci` (Node 20, `cache: npm`). The tree contains **no `package-lock.json`** (none exists at any examined snapshot). Running that step as written:
```text
$ npm ci --no-audit --no-fund

npm error

npm error npm-shrinkwrap.json with lockfileVersion >= 1. Run an install with npm@5 or
npm error later to generate a package-lock.json file, then try again.
```
This is independent of the auditor's environment. A later commit on the unmerged stack, `09c1a3b` (2026-10-18), *"ci: lockfile-free install in community CI (was cache:npm + npm ci with no lockfile)"*, confirms the step was broken until then.

Recount script (reproducible):
```js
// node recount.mjs <checkout>
import fs from "fs"; import path from "path";
const wt = process.argv[2], d = (p) => path.join(wt, "data", p);
const files = fs.readdirSync(d("nodes")).filter(f => f.endsWith(".json"));
const nodes = files.flatMap(f => { const c = JSON.parse(fs.readFileSync(d("nodes/" + f), "utf8")); return Array.isArray(c) ? c : []; });
const bench = fs.existsSync(d("benchmarks.json")) ? JSON.parse(fs.readFileSync(d("benchmarks.json"), "utf8")) : [];
const domains = fs.readdirSync(d("domains")).filter(f => f.endsWith(".json")).length;
console.log({ nodes: nodes.length, unique: new Set(nodes.map(n => n.id)).size, benchmarks: bench.length,
  master_canon: nodes.length + bench.length, domains,
  edges: nodes.reduce((a, n) => a + (n.edges || n.relationships || []).length, 0) });
```
